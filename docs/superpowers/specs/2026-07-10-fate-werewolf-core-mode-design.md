# 命运狼人核心模式设计

## 目标

把命运狼人 V3 的核心模式实现为可完整游玩的网页派对游戏：大屏负责公开阶段与主持节奏，手机负责角色私密信息和合法操作，服务端拥有全部规则真相。

首发支持 6–10 人；扩展角色与具体命运牌内容暂不实现，但必须拥有稳定注册位置，避免以后重写昼夜流程。

## 范围

首发核心角色：村民、狼人、神谕者、命运编织者、月光守护者、猎人。

本轮实现：角色发放、首夜与常规夜晚、死亡、猎人陪葬、白天两轮发言流程、投票和 PK、死亡玩家命运议会、大小阿卡纳占位抽取与公开展示、游戏历史、核心胜负判定和手机端个人工具。

本轮不实现：丘比特、焚焰者、梦境使者的具体规则；大小阿卡纳的具体效果；真实身份访问鉴权。私密状态接口仅作为可信房间原型使用。

## 规则边界

### 阵营与胜利

- 月神阵营：消灭所有存活的狼人及未来接入的敌对第三阵营。
- 狼神阵营：消灭所有存活的月神阵营及敌对第三阵营；不再以人数优势获胜。
- 核心模式不存在可获胜的第三阵营，但胜利检查以可注册的第三阵营胜利检查器执行，扩展角色接入时不需要改流程。
- 每次死亡、夜晚结算和白天放逐后均立即检查胜利；检查顺序固定为恋人/丘比特扩展、其他第三阵营、狼神阵营、月神阵营。

### 夜晚

首夜与常规夜晚均从存活角色模块生成行动队列。核心顺序：守护者 → 狼人 → 命运编织者 → 神谕者。未来角色可声明首夜专属或常规夜晚步骤，并指定顺序。

狼人每人秘密提交“击杀目标 / 不行动 / 自我牺牲”；服务器在夜晚结算时统一解析。命运编织者只在狼人行动已锁定后可获知目标，并选择杀人、救人、守护或跳过。守护者不能连续守护同一对象。猎人被杀人牌杀死时不能触发陪葬；其他死亡原因可在结算窗口选择一名存活玩家或跳过。

### 命运系统占位

每张命运牌使用统一定义：`id`、`arcanaType`（`minor` 或 `major`）、`tendency`、`title`、`text`、`trigger`、`effectKey`。

- 夜晚结算与死亡处理完成后进入命运议会。
- 所有死亡玩家对神谕、守护、混乱、黑暗四种倾向投票；票数只改变各倾向牌的抽取权重，不能指定牌。
- 议会结束后服务器根据权重抽牌，写入当前回合与历史；大屏公开牌名和文本。
- 小阿卡纳每轮使用占位牌池；大阿卡纳仅在 `trigger` 条件满足时加入候选池。首发可使用稳定的占位触发器：首个狼人死亡、终盘（存活人数不超过 4）、连续两晚无人死亡。
- 所有首发卡的 `effectKey` 为 `placeholder`：记录“已处理”，不改变任何玩家、票数或胜负。以后替换具体效果必须通过受测的效果解析器。
- 命运赐福在首发保留状态和展示入口，但不随机发放个人牌；具体个人塔罗内容确认后再启用。

### 白天

白天按命运牌揭示 → 命运赐福占位 → 夜晚结果/遗言 → 第一轮顺序发言 → 第二轮自愿发言 → 投票 → PK（如需要）→ 放逐 → 胜利检查推进。

大屏显示当前发言人、存活名单、投票进度和公开历史。服务器保存第一轮发言索引及第二轮报名顺序；只有存活玩家可报名和投票，PK 候选人不能参加 PK 投票。死亡玩家在白天无任何操作。

## 架构

`games/werewolf/server/` 作为权威规则层，拆分为：

- `roles/`：角色定义与可扩展 `RoleModule` 注册表；每个模块提供夜晚步骤、私密状态投影、行动校验、结算钩子和可选胜利检查。
- `fate/`：牌定义、权重抽取、触发器和占位效果解析。
- `resolvers/`：夜晚死亡、恋人扩展链、猎人陪葬、投票/PK、胜利判定。
- `game.js`：创建状态、阶段转换和运行时适配器，不再承载所有角色细节。

服务端状态包含原始私密真相；`publicWerewolfState` 只投影公开信息；`privateWerewolfState` 为单个手机投影其角色、行动、个人工具和允许观察的信息。客户端不得决定阶段、死亡、抽牌或胜负。

## 手机与大屏交互

手机根据私密动作模型渲染一次一个明确操作：确认角色、守护、狼人行动、编织者选牌/选目标、神谕确认、猎人陪葬、命运议会投票、第二轮发言报名、投票和 PK 投票。

动作模型须显式支持单选、多选、卡牌选择、可选目标与提交状态，不能复用一个 `targetId` 承载不同语义。丘比特以后通过 `multi-target` 动作接入。

手机本地保存怀疑名单、信任名单和推理笔记；服务端公开历史提供夜晚结果、放逐、投票结果和命运牌记录。死亡玩家在夜间获得“观察中”状态，但核心模式首发不提供额外身份/行动细节；扩展观察可见性由角色模块和私密投影增加。

大屏不显示任何私密角色或测试控制。主持控制独立于玩家手机，支持推进、暂停、恢复和开发模式自动填充；开发模式必须显式开启。

## 测试与验收

- Vitest 将包含 `games/werewolf/**/__tests__`，而不是只运行 `src/__tests__`。
- 规则测试覆盖角色牌组、每个夜晚动作的合法/非法输入、守护限制、狼人行为、编织者三张牌、猎人死亡限制、投票/PK、胜负顺序和命运权重抽取。
- 集成测试从 6、8、10 人模拟局推进到结束，验证公共状态不泄漏角色、手机仅获得当前合法动作、命运议会投票发生在抽牌之前。
- UI 测试覆盖多选和卡牌选目标的手机交互、第二轮报名、个人笔记及历史展示。
- 验收时以真实手机浏览器和大屏各跑一局 6、8、10 人模式。

## 实施顺序

1. 建立测试覆盖与类型/状态契约。
2. 拆分角色、夜晚、胜利与命运占位引擎，修正 P0 规则问题。
3. 对齐服务端动作模型与手机端交互。
4. 完成白天流程、个人工具、历史和大屏主持控制。
5. 用整局模拟、构建和设备手测验收。
